# Trip Service

Учебный сервис для работы с поездками на Go и PostgreSQL.

Сервис позволяет:

- создавать поездку;
- получать поездку по идентификатору;
- завершать активную поездку;
- проверять состояние процесса и доступность базы данных.

## Окружение

Для работы нужны Go, Docker и `tripgoctl`.

Поднять окружение лабораторной работы 2:

```bash
tripgoctl cluster start
tripgoctl environment start
tripgoctl connect
```

`tripgoctl` создаёт локальный файл `.env` с адресами компонентов. В
окружение входят PostgreSQL, OpenTelemetry Collector, Jaeger, Prometheus и
Grafana. Адреса веб-интерфейсов выводит `tripgoctl connect`.

Применить миграции:

```bash
make migrate
```

Посмотреть их состояние:

```bash
make migrate-status
```

Запустить сервис:

```bash
make run
```

Цель `run` сначала загружает значения из `.env.example`, затем локальные
значения из `.env`. Локальные значения имеют приоритет.

## Архитектура

Зависимости создаются и связываются вручную в `internal/container`.
`main` читает конфигурацию, создаёт контейнер, запускает HTTP-сервер и
управляет остановкой приложения.

Путь запроса:

```text
HTTP-обработчик → usecase → доменная модель и репозиторий → PostgreSQL
```

Основные пакеты:

- `internal/http/trip/create`, `get`, `finish` — HTTP-обработчики действий;
- `internal/transport/http` — адаптер к сгенерированному OpenAPI-интерфейсу,
  а также обработчики health и ready;
- `internal/usecase/trip` — сценарии создания, получения и завершения поездки;
- `internal/domain/trip` — модель поездки, её валидация, переход состояния
  и доменные ошибки;
- `internal/domain/validation` — тип ошибки валидации с полем и причиной;
- `internal/model` — общее имя модели для обмена между слоями;
- `internal/repository/trip` — сохранение и получение данных поездки;
- `internal/infra/postgres` — подключение и инструментирование PostgreSQL;
- `internal/infra/postgres/transaction` — менеджер транзакций;
- `internal/infra/telemetry` — провайдеры трасс и метрик, события поездок;
- `internal/http/domainerror` — перевод ошибок приложения в HTTP-ответы;
- `internal/http/middleware` — восстановление после паники, логи и метрики.

Интерфейсы зависимостей объявлены в пакетах-потребителях: HTTP-обработчики
зависят от интерфейсов usecase, а usecase — от интерфейсов репозитория и
менеджера транзакций. Это позволяет подменять реализации моками в unit-тестах.

OpenAPI-код ожидает единый объект с методами всех HTTP-операций. Поэтому
в `internal/transport/http` находится адаптер, который передаёт вызовы
обработчикам отдельных действий в `internal/http/trip/create`, `get` и
`finish`. Проверки health и ready также находятся в адаптере.

Репозиторий и инфраструктура размещены в отдельных директориях. Имена
Go-пакетов `repository`, `db` и `txmanager` сохранены после переноса из
первой работы, чтобы не менять все обращения к ним. Эти пакеты не
используются напрямую в HTTP-обработчиках.

## Транзакции и конкурентные запросы

Используется уровень изоляции PostgreSQL `Read Committed`: каждый SQL-запрос
видит только данные, зафиксированные до его начала.

Создание поездки включает две записи — в `trips` и `trip_status_history`.
Обе выполняются в одной транзакции: при ошибке изменения откатываются.

Корректность конкурентных операций обеспечивается не только уровнем
изоляции:

- частичный уникальный индекс не позволяет создать две активные поездки
  одному водителю;
- условие `status = 'active'` в `UPDATE` позволяет завершить поездку только
  одному из конкурирующих запросов.

Менеджер транзакций передаёт транзакцию через `context`. Вложенный вызов
переиспользует существующую транзакцию.

## HTTP API

Проверить работу процесса:

```bash
curl -i localhost:8080/health
```

Проверить доступность базы:

```bash
curl -i localhost:8080/ready
```

Создать поездку:

```bash
curl -i -X POST localhost:8080/api/v1/trips \
  -H 'Content-Type: application/json' \
  -d '{
    "user_id": "5cb72c04-7650-45c9-a79b-bcdba0631e0c",
    "driver_id": "8860b315-ec86-42eb-a17c-7c163d721ff5",
    "start_point": {"latitude": 59.9398, "longitude": 30.3146},
    "end_point": {"latitude": 59.9290, "longitude": 30.3626},
    "price": 1450
  }'
```

Получить поездку:

```bash
curl -i localhost:8080/api/v1/trips/<trip-id>
```

Завершить поездку:

```bash
curl -i -X POST localhost:8080/api/v1/trips/<trip-id>/finish
```

Ошибки возвращаются в формате `application/problem+json`. Поле `code`
содержит стабильный машиночитаемый код ошибки. Внутренние детали ошибки
базы в HTTP-ответ не попадают.

## Телеметрия

Сервис использует OpenTelemetry для трасс и метрик и `log/slog` для
структурированных JSON-логов.

HTTP-запрос создаёт спан; операции PostgreSQL отображаются вложенными
спанами. В логе запроса есть `trace_id` и `span_id`: по `trace_id` можно
найти тот же запрос в Jaeger.

Инструментирование PostgreSQL выполняется на уровне пула через `otelpgx`.
Дополнительный адаптер распознаёт таблицы `trips` и `trip_status_history`
и добавляет их имена к соответствующим спанам и метрикам.

Метрики можно посмотреть в Grafana через источник Prometheus, например:

```text
http_server_request_duration_seconds_count
http_server_active_requests
db_client_operation_duration_seconds_count
tripgo_trips_created_total
tripgo_trips_completed_total
tripgo_trips_active
```

Адрес коллектора, протокол и параметры трассировки задаются стандартными
переменными OpenTelemetry. Если коллектор недоступен, сервис продолжает
отвечать на запросы.

## Тесты и линтер

Запустить обычные тесты дважды с проверкой гонок и отчётом покрытия
домена и usecase:

```bash
make test
```

Запустить интеграционные тесты с PostgreSQL:

```bash
tripgoctl environment start
make migrate
make test-integration
```

Интеграционные тесты создают собственные данные и удаляют их после проверки.
В том числе проверяется откат записи поездки и истории при ошибке транзакции.

Для `make lint` нужен golangci-lint 2.15.0 в локальной папке `bin`:

```bash
mkdir -p bin
curl -sSfL https://golangci-lint.run/install.sh | sh -s -- -b ./bin v2.15.0
make lint
```

## Генерация кода

Сгенерировать OpenAPI-код и моки интерфейсов:

```bash
make generate
```

Сгенерированный OpenAPI-код находится в `api/api.gen.go`. Моки создаются
рядом с контрактами в файлах с суффиксом `_test.go`.

## Конфигурация

Пример переменных находится в `.env.example`. Основные группы:

- `HTTP_ADDR` и `HTTP_*_TIMEOUT` — адрес и таймауты HTTP-сервера;
- `LOG_LEVEL` — уровень логирования;
- `SHUTDOWN_TIMEOUT` — общий бюджет остановки;
- `DATABASE_*` — подключение, параметры пула и таймауты PostgreSQL;
- `OTEL_*` — стандартные настройки OpenTelemetry.

`.env` — локальный файл, его не нужно добавлять в Git.

## Остановка

Сервис обрабатывает `SIGINT` и `SIGTERM`: прекращает приём запросов,
дожидается текущих и закрывает ресурсы. Если срок `SHUTDOWN_TIMEOUT`
истёк, сервер принудительно закрывает соединения.

## Дополнительные решения

- `Read Committed` выбран как стандартный уровень PostgreSQL: для операций
 сервиса достаточно видеть зафиксированные данные, а конкурентную защиту
  обеспечивают уникальный индекс и условный `UPDATE`. Уровень задаётся явно
  при открытии транзакции.
- `model.Trip` является псевдонимом доменной модели. Это позволяет передавать
  один и тот же тип между слоями, не создавая вторую копию данных поездки.
- OpenAPI-адаптер объединяет методы, ожидаемые сгенерированным интерфейсом,
  и передаёт вызовы отдельным обработчикам действий.
- Внешний `Recover` защищает всю цепочку middleware; внутренний позволяет
  логированию и метрикам увидеть ответ `500`, если паника произошла в
  обработчике.
- Метрика активных поездок считывает текущее число из БД, поэтому сохраняет
  корректное значение после перезапуска сервиса.
- Адаптер SQL-телеметрии распознаёт две таблицы текущего сервиса. При
  добавлении других таблиц его правила определения имени нужно расширить.
- Для `make test` явно указан `GOTOOLCHAIN=go1.26.0+auto`: это обходит
  ошибку поиска `covdata` при автоматическом переключении версии Go.
